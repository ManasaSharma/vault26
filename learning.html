Architecture

Two views: what exists today and what the notes propose.

Current portfolio

Next.js App Router

src/app/layout.tsx → src/app/page.tsx

↓

Portfolio sections

Hero · Stats · Education · Skills · Experience · Projects · Contact

↓

Presentation

React props + Tailwind utilities + CSS animations

Client interactions

Header uses local React state. visitorStore.ts persists visitor type and banner state through Zustand middleware.

Additional capabilities

GlobeScene.tsx uses Three.js / React Three Fiber / Drei. React Query and GraphQL packages are installed; integration is not established by this inspection.

Proposed JSON API flow

Browser / client component

fetch('/api/data') → loading / error / success states

↓ HTTP request

Next.js route handler

src/app/api/data/route.ts → Node.js fs → public/data.json

↓ JSON response

React section

Render data as props → Tailwind styles → optional animation

A server component can also read data directly on the server. An internal HTTP call is optional when the content is already available during server rendering.

Boundaries to remember

  • Node.js fs stays on the server; do not import it into a client component.
  • Files in public/ are public assets. Never put secrets or private records in data.json.
  • Repository JSON is a versioned content file, not a transactional database.
  • Deploy changes to repository content; deployed files are not a reliable writable database.
  • Zustand holds interaction state. Portfolio content and cached server data have different responsibilities.

Example route · future implementation

// src/app/api/data/route.ts — Node runtime
import { readFile } from 'node:fs/promises';
import path from 'node:path';

export const runtime = 'nodejs';

export async function GET() {
  try {
    const file = path.join(process.cwd(), 'public', 'data.json');
    const data = JSON.parse(await readFile(file, 'utf8'));
    return Response.json(data);
  } catch {
    return Response.json({ error: 'Unable to load portfolio' },
      { status: 500 });
  }
}

Illustrative only. Validate the content schema and verify deployment file tracing if you implement this reader.

Build workflow

A repeatable path from learning to a working feature.

  1. Pick one section. Start with Experience or Projects.
  2. Define the data. Keep content separate from layout; decide between inline objects, an import, or an API.
  3. Build the component. Pass typed props and reuse the design tokens.
  4. Add behavior. Choose local state, shared state, or fetched data deliberately.
  5. Check the result. Review desktop and mobile, keyboard navigation, and failure states.
  6. Record the lesson. Add decisions, errors, and changes below, then commit.

Commands available in this repository

npm run dev     # Local development
npm run build   # Production build
npm run start   # Run an already-built app
npm run lint    # ESLint

Errors & changes

Capture the why, not just the fix.

No specific build error was included in the notes. Record the exact message and context before choosing a fix.

Development restart checklist

  1. Stop the active development process with Ctrl+C in its terminal.
  2. Restart with npm run dev and capture the full error if it returns.
  3. If evidence points to a stale build cache, remove only the repo’s generated .next directory after stopping the server, then restart.

Avoid broad process-kill commands: they can stop other Next.js projects. Cache cleanup is a troubleshooting step, not a fix for every build error.
